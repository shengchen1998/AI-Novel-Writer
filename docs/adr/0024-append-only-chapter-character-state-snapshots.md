# 章节角色状态采用追加式快照与可重建缓存

角色动态状态仍不是第二套作者事实。每次定稿后处理复用同一次角色提取结果，按该次定稿来源追加一份所有已识别角色的完整动态状态快照，逐字段保留作者输入、定稿派生、legacy、已知时点与正文证据；普通定稿不因此增加模型调用。受保护字段的分歧仍是待确认候选，未知或歧义身份不按姓名猜测合并。`characters.currentState` 继续作为最新缓存，不再承担章节状态历史；快照追加与缓存更新分离，缓存冲突不得回滚已验证快照或覆盖作者编辑。本决定扩充 ADR 0017，不以快照取代结构化角色名单或不可变定稿原文。

快照以最近一份较早的有效快照为基线，叠加已知时点不晚于本章的作者字段及本章派生补丁；没有前驱时只从符合时点的角色名单资料建立初始基线。快照整体绑定本次定稿，继承字段仍保留各自最初的来源。只有与当前权威定稿及连续前驱基线一致的快照有效；同章重定稿、早章变更和章节顺序变化使受影响后缀失效，前驱缺口不得跳过。作者后续编辑不回写或使历史快照失效，最新缓存确定性叠加当前作者事实。

快照用于历史查看、字段差异、缓存重建和原文定位，不直接升级为生成或审稿事实。提取失败不阻塞单章正文定稿，但自动批量创作必须停止；作者可在排除失效派生状态的降级上下文里继续创作。显式重建须经作者确认并重新执行提取，不得直接重放旧基线上的字段补丁；重建逐章追加、保留断点，缓存只在连续状态链到达最新权威定稿后恢复有效。任意旧快照不提供一键覆盖当前状态的操作。

快照通过稳定角色 ID 关联既有定稿身份快照，改名、退役、合并或删除不回写历史，也不在缓存重建时复活失效身份。重定稿产生的旧快照继续保留；作者显式删章时，本章各版本快照依 ADR 0011 随本章定稿事实删除，不留无来源快照。旧项目升级和原稿导入不自动调用 AI 回填历史。

快照使用独立的追加式存储，内容只在成功校验后写入，待处理与失败状态属于后处理运行；数据库禁止更新快照内容，但允许删章级联删除。定稿 ID 与重建运行 ID 共同标识逻辑快照生成，同一运行重试保持幂等。版本化迁移只创建结构，不解析旧文本快照或伪造历史；备份与恢复保留快照及来源关系，但不自动重放旧生成运行。
